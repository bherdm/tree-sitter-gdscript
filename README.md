## Multi-version Godot support

This grammar is a **superset** that parses GDScript from three Godot generations
with a single parser:

| Godot   | GDScript era                                                            |
|---------|-------------------------------------------------------------------------|
| 2.x     | `tool`, `export(Type, …)`, `onready`, `setget`, `yield(…)`, `.base()`   |
| 3.x     | `class_name`, static type hints, `match`, RPC keywords (`remote`/`master`/`slave`/`puppet`/`sync`/…), `is`/`as` |
| 4.x     | `@annotations`, `await`, `super`, inline `get:`/`set:`, typed collections `Array[T]`/`Dictionary[K,V]`, lambdas |

Because a tree-sitter grammar compiles to one parser, it accepts the union of all
three dialects rather than rejecting version-wrong syntax. Correctness is proven
against the **real Godot binaries**: every file under `test/godot_corpus/{v2,v3,v4}`
is accepted by that version's Godot with zero errors, and the grammar parses all of
them with zero `ERROR`/`MISSING` nodes. See [`test/godot_corpus/README.md`][corpus]
for the corpus and the Godot-oracle test harness, and
[`test/godot_corpus/known_limitations/`][limits] for the single valid-but-pathological
construct intentionally left uncovered (a lambda used as a ternary *condition*).

Requires the tree-sitter CLI ≥ 0.26 (ABI 15).

## How To

- Test grammar
  1. `npm run genTest`
- Test scanner
  1. Edit "src/scanner.c"
  1. `npm run test`, no need to generate.
- Build prebuilds
  1. `npm run genTest`
  1. `npm run prebuild`
- Build with node-gyp
  1. `npm run genTest`
  1. `npm install node-gyp`
  1. `node-gyp rebuild`
- Edit
  1. Write tests in corpus to express behavior.
  1. Make grammar or scanner edits.
  1. See above for running tests.
  1. `npm run format`
  1. Commit changes.
     - If commit is an issue fix, prefix message with `fix #<issue-number>:`
     - List the rules changed in commit message.
     - Note what rules need to be updated in [nvim-treesitter][] queries.
  1. Commit generated files with the latest non-wip commit.
  1. Push
- Release
  1. Manually edit version in package files: CMakeLists.txt, Cargo.toml,
     Makefile, pyproject.toml, tree-sitter.json
  1. `npm version --git-tag-version false <major, minor, patch>`
  1. `git tag -a v<version>`
  1. `git push && git push --tags`
  1. `cargo package`
  1. `cargo publish`

Note: `node-gyp-build` will check for binaries in both `build` and `prebuilds`
directories.
